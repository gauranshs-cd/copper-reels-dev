Document 1: Product Requirements Document (PRD) — Copper Reels

Version: 1.0
Owner: You
Last updated: {{today}}


1) Product Summary

Copper Reels converts a single mission statement—“I help X achieve Y”—into a complete, editable YouTube content strategy: audience/positioning, idea generation, titles/thumbnails, script & storyboard, and a teleprompter-ready script. The user advances through a 3‑step wizard with an animated “one‑pager” reveal, selects ideas, and finalizes a plan. The app remembers the latest draft and lets users add reference YouTube videos to guide style.


2) Goals & Non‑Goals

Goals

  • Reduce the time from idea → publishable plan to under 10 minutes for a first draft.
  • Make every AI artifact editable; preserve changes across sessions.
  • Provide guided defaults with optional “inspiration videos” to influence style without copying.
  • Produce usable outputs: title options, thumbnail briefs, script bricks, storyboard, teleprompter view, and exports.

Non‑Goals

  • Full YouTube scheduling/posting.
  • Advanced analytics beyond basic performance notes.
  • Long-form multi-person collaboration (comments/roles) in v1.


3) Personas

  • Solo Creator (primary): New or growing creators needing structure and speed.
  • Producer/Editor (secondary): Helps a host plan episodes quickly.
  • Agent/Consultant (secondary): Generates strategies for multiple clients.


4) User Stories (Must‑Have)

  1. As a creator, I can enter “I help X achieve Y” and click Run to generate an animated one‑pager (Audience Avatar, Viewer Type, Content Pillars).
  2. As a creator, I can edit any section inline; edits persist and mark downstream items as stale until I regenerate.
  3. I can paste YouTube links as inspirations, tag what to borrow (e.g., hook style, pacing), and weight them (1–5).
  4. I can hit Next to view 12–20 ideas, shortlist 1–3, then pick 1 to plan.
  5. For the chosen idea, I see 6 title options (with guidance) and 2–3 thumbnail briefs, and I choose one of each.
  6. I get a brick‑based script (Intro, Middle x2–4, Example, Application, optional Outro) + visual storyboard frames.
  7. I can toggle a Teleprompter view (full screen, speed/font controls) that renders the script cleanly.
  8. I can export: Markdown script, B‑roll CSV, YouTube description/chapters/tags.
  9. On returning, my most recent draft auto‑loads; I can tweak the mission statement and regenerate.


5) End‑to‑End Flow

Step 1: Onboarding → Input mission statement + (optional) channel about + goal → Click Run → Animated one‑pager fills in.
Step 1.5: Inspirations → Paste links → tag traits → weights.
Step 2: Ideas → Grid of ideas → shortlist → pick one → Next.
Step 3: Plan → Titles, thumbnail briefs, bricks + storyboard → Teleprompter → Export.


6) Functional Requirements (FR)

FR‑1: Onboarding Form

  • Fields: umbrella (required), channelAbout (optional), primaryGoal (choices).
  • CTA: Run triggers LLM foundation; output animates in place.
  • Accept inline edits; edits flip downstream flags patternBankStale, ideasStale, planningStale.

FR‑2: Animated One‑Pager

  • Sections: Audience Avatar, Viewer Type (+ rationale), Content Pillars, Channel Promise (derived).
  • Skeleton → type‑in reveal; progress bar 0–100%.
  • Each section supports Regenerate (local) and Lock (prevent overwrite).

FR‑3: Inspirations Drawer

  • Paste multiple YouTube URLs → fetch title, channel, duration, publishedAt, thumbnail.
  • Tag chips: title_vibe, hook_style, pacing, visual_motif, structure, cta_style, editing_style.
  • Weight slider 1–5; notes textarea.
  • Derived styleGuide flows into Ideas/Titles/Thumbs/Script prompts.

FR‑4: Ideas Hub

  • Generate 12–20 ideas from foundation + pattern bank + styleGuide.
  • Card shows: concept, pillar, difficulty badge (1–5), why‑it‑clicks, thumbnail hint.
  • Actions: shortlist (multi), Refresh with filters (“more beginner”, “contrarian”, “shorter”).

FR‑5: Title & Thumbnail Selection

  • Titles: 6 options with score (0–1), shape label, micro‑guidance.
  • Thumbnails: 2–3 briefs (overlay text ≤ 4 words, subject, composition, color mood, props, shot list, avoid, model prompt, negative prompt).
  • Choose one title + one brief; store in plan.

FR‑6: Script & Storyboard (Bricks)

  • Bricks: INTRO → 2–4 MIDDLE → EXAMPLE → APPLICATION → (optional) OUTRO.
  • Each brick: narration, on‑screen text (≤ 8 words), callouts, B‑roll, beats.
  • Storyboard frames aligned to bricks with shot types and assets to prep.

FR‑7: Teleprompter

  • Full‑screen, adjustable speed/font, mirrored mode, scene markers, elapsed/remaining timer.

FR‑8: Exports

  • Markdown script; CSV B‑roll; chapters/description/tags (SEO) block.

FR‑9: Persistence & Memory

  • Auto‑save brief to DB + localStorage; auto‑load last draft on arrival.


7) Non‑Functional Requirements (NFR)

  • Performance: First paint < 2s; LLM roundtrips streamed; wizard navigation instant.
  • Reliability: Autosave every 2s idle; draft recovery after refresh.
  • Security: Token‑based auth; secrets in vault; audit logs for generation calls.
  • Accessibility: Keyboard nav; WCAG AA contrast; screen‑reader labels.
  • Internationalization: Copy and date formats separable; English first.
  • Privacy: Store minimal YouTube metadata; no raw copyrighted content.


8) Success Metrics (V1)

  • TTFP (time to first plan): median ≤ 10 min.
  • % users who complete Step 3 after Step 1: ≥ 50%.
  • Avg. edits per brick: ≤ 3 (indicates quality).
  • Export usage rate: ≥ 40% of sessions.


9) Milestones

  • M1 (Foundation & Ideas): Onboarding → one‑pager → inspirations → idea grid.
  • M2 (Plan): Titles/Thumbnails → bricks/storyboard → teleprompter.
  • M3 (Polish): Exports, stale indicators, autosave, A11y, perf.


10) Risks & Mitigations

  • LLM variance: Provide Regenerate per‑section + Lock.
  • YouTube API limits: Cache results; throttle; degrade gracefully (titles only).
  • Scope creep: Keep v1 to 3 steps; defer analytics and scheduling.


11) Acceptance Criteria (DoD)

  • All FRs implemented; JSON outputs validated; editable artifacts persist.
  • One‑pager animates; stale flags behave; inspirations influence is observable.
  • Teleprompter fully functional; exports produce valid files.


12) Glossary

  • CreativeBrief: Canonical state derived from onboarding + inspirations.
  • Pattern Bank: Extracted title/thumbnail patterns from niche videos.
  • Bricks: Script blocks (Intro/Middle/Example/Application/Outro).

🧩 Document 2: Architecture & Technical Design — Copper Reels

Version: 1.0


A) System Overview

A Next.js web app with server routes orchestrating LLM “bots” and background jobs. State centers on a CreativeBrief that feeds deterministic pipelines: Foundation → Pattern Bank → Ideas → Titles/Thumbs → Script/Storyboard → Exports.


B) Tech Stack (recommended)

  • Frontend: Next.js 14 (App Router) + TypeScript + Tailwind + Framer Motion + TipTap
  • State: Zustand (client), React Query (server)
  • Backend: Next Route Handlers or NestJS; tRPC/HTTP
  • DB: Postgres (Prisma)
  • Cache/Queue: Redis + BullMQ
  • Storage: S3 (thumbnails/exports)
  • LLM Orchestration: minimal functions or LangGraph
  • Auth: NextAuth (Google/Email)
  • Telemetry: PostHog + structured logs


C) High‑Level Architecture (text diagram)

UI (Next.js + Tailwind + Framer Motion)

   ├─ Onboarding (Run) → /api/foundation/generate ─→ LLM (Positioning Bot)

   │      └─ Save: Avatar, ViewerType, Pillars → Postgres (CreativeBrief)

   ├─ Inspirations Drawer → /api/inspirations/meta → YouTube Data API

   │      └─ StyleGuide JSON → stored in CreativeBrief

   ├─ Ideas Hub → /api/ideas/generate ─→ LLM (Ideation Bot)

   ├─ Plan Page

   │      ├─ /api/titles/generate → LLM (Title Bot)

   │      ├─ /api/thumbnails/generate → LLM (Thumb Brief Bot)

   │      └─ /api/script/generate → LLM (Script & Storyboard Bot)

   └─ Exports

          ├─ /api/export/script.md

          └─ /api/export/broll.csv

Redis (caching; job status)  |  BullMQ (background thumbnail renders if using image gen)

S3 (assets, exports)         |  Postgres (projects, ideas, plans)


D) Data Model (key entities; Prisma‑style)

Channel(id, name, umbrella, viewerType, avatarId, createdAt, updatedAt)

AudienceAvatar(id, channelId, demographics JSON, psychographics JSON)

Pillar(id, channelId, name, summary)

PatternBank(id, channelId, powerWords[], titleShapes JSON, thumbPatterns JSON, sources JSON)

Idea(id, channelId, pillarId?, status, concept, whyItWillClick, difficulty, thumbnailHint, chosenTitle?, chosenThumb?)

TitleDraft(id, ideaId, text, score, shape, powerWordsUsed[])

ThumbDraft(id, ideaId, url|s3Key, notes)

VideoPlan(id, ideaId, bricks JSON[], storyboard JSON[], chosenTitle, chosenThumbBriefIndex)

Inspiration(id, channelId, url, title, channelTitle, durationSec, publishedAt, tags[], weight, notes)

CreativeBrief is a composition of Channel + Avatar + Pillars + PatternBank + Inspirations + Ideas + Plan + Status Flags.


E) State & Dependency Graph

  • Editing umbrella or pillars sets: patternBankStale=true, ideasStale=true, planningStale=true.
  • Adding inspirations sets: ideasStale=true, planningStale=true.
  • Changing chosen title sets: planningStale=true.

Store status with booleans; surface as small amber dots in UI.


F) APIs (contract sketches)

POST /api/foundation/generate
Input: { umbrella, about?, goal? }
Output: { avatar, viewerType, pillars, rationale }

POST /api/inspirations/meta
Input: { urls: string[] }
Output: { videos: { url, title, channel, durationSec, publishedAt, thumbnail }[] }

POST /api/ideas/generate
Input: { briefId, foundation, patternBank?, styleGuide? }
Output: { ideas: Idea[] }

POST /api/titles/generate
Input: { briefId, idea, patternBank?, styleGuide? }
Output: { titles: TitleDraft[] , guidance }

POST /api/thumbnails/generate
Input: { briefId, idea, patternBank?, styleGuide? }
Output: { briefs: ThumbBrief[] }

POST /api/script/generate
Input: { briefId, idea, chosenTitle, styleGuide? }
Output: { runtimeEstimateSec, bricks[], storyboard[], metadata }

GET /api/export/script.md?planId=... → stream Markdown
GET /api/export/broll.csv?planId=... → stream CSV

All LLM responses validated by Zod; reject with actionable error messages.


G) LLM Orchestration

Bots (from your prompt pack):

  1. Positioning Bot → foundation
  2. Skyscraper Query Expansion → queries (optional in v1)
  3. Pattern Bank Analysis → title/thumbnail patterns (optional in v1)
  4. Idea Generator → ideas
  5. Title Generator → 6 alts + scores
  6. Thumbnail Brief Generator → 2–3 briefs
  7. Script & Storyboard Bot → bricks + frames
  8. B‑roll Extractor → consolidated list

StyleGuide derived from inspirations gets appended to USER message for 4–7.


H) Error Handling & Retries

  • LLM: validate JSON → if invalid, single auto‑retry with stricter temperature (e.g., 0.1).
  • Network: exponential backoff (200ms, 800ms, 2s).
  • User‑visible: toast with “Try again” + show raw validation error keys.


I) Observability

  • Log each generation: {bot, durationMs, tokens, success, staleInputs}.
  • Track step completion events: onboarding_run, ideas_shortlisted, plan_exported.


J) Security & Secrets

  • Environment secrets via platform vault.
  • Signed upload URLs for S3.
  • Limit YouTube metadata storage to essentials.


K) Deployment & Environments

  • Envs: dev, staging, prod.
  • CI: typecheck, lint, unit tests; pull request previews.
  • CD: blue‑green or rolling; feature flags for risky changes.
